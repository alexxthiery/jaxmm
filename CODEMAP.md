# Codemap: jaxmm

> Coordinate API updated: 2026-11-11 (historical line/test counts below are approximate)

Pure JAX molecular potential energy. OpenMM extracts force field params once;
energy evaluation is pure JAX (jit, vmap, grad). Built for training normalizing
flows against Boltzmann targets without the CPU-GPU bottleneck of calling OpenMM
per sample.

## Module dependency graph

```
_validation.py     JAX/NumPy checks, no energy dependency
batching.py        JAX event mapping, no molecular dependency
extract.py         parameter pytrees; OpenMM extraction is lazy
coordinates.py    _validation + extract's pytree helper
internal.py       coordinates + _validation + batching
energy.py         extract types + _validation; one component dispatcher
utils.py          energy + internal + batching + jaxopt
integrate.py      energy + utility constants
notebook.py       lazy plotting/viewer integration
```

`InternalCoordinates.pullback` composes a Cartesian density with physical or
fixed-frame volume and safe support rejection. It does not know force fields.
`total_energy` sums `energy_components`; do not add a second force-term dispatcher.

## Data flow

```
OpenMM System
    |
    v
extract_params()  -->  ForceFieldParams (frozen dataclass, JAX pytree)
                            |
                       save_params() / load_params()  (.npz, no pickle)
                            |
                            v
                   total_energy(positions, params) --> scalar (kJ/mol)
                            |
                   +--------+--------+
                   |                 |
                   v                 v
              jax.grad          jax.vmap / jax.jit
              (forces)          (batch eval)
                   |
                   v
         minimize_energy()  /  verlet()  /  langevin_baoab()
```

## Entry points

- **Library**: `import jaxmm; params = jaxmm.extract_params(system)`
- **Tests**: `python -m pytest tests/ -v` (324 tests, 93% branch coverage)
- **Examples**: `examples/quickstart/quickstart.py` (start here)
- **Demo**: `examples/jaxmm_demo/jaxmm_demo.py`

## Patterns

- All energy functions: `(positions, params) -> scalar` (pure, no side effects)
- Frozen dataclasses as param containers, registered as JAX pytrees via `_register_pytree()`
- Batch eval: `jax.vmap(jaxmm.total_energy, in_axes=(0, None))`
- Integrators: nested `jax.lax.scan` (inner for stepping, outer for saving)
- Test validation: each term tested against isolated OpenMM force (not force group API)
- Optional fields (gbsa, rb_torsions, cmap, restraints): `None` when absent, custom pytree flatten/unflatten
- Gradient safety: `jnp.sqrt(r_sq + 1e-30)` instead of `jnp.linalg.norm` (avoids NaN grad at zero),
  and `atan2(|u x v|, u . v)` instead of `arccos` for angles (avoids NaN grad at 0 and pi)
- Metadata validation is host-side (numpy) and separate from the traced transforms,
  so `validate_zmatrix` can raise clear errors without breaking jit
- Defensive boundary checks: static shape and atom-count checks always run;
  index-bound checks run eagerly and are skipped under jit/vmap where values are tracers

## Units

Internal: nm, ps, kJ/mol, K, amu, elementary charge (matches OpenMM).
Unit constants multiply to convert: `dt = 1.0 * FEMTOSECOND` gives `0.001` ps.

## Dependencies

Core: `jax`, `numpy`, `jaxopt`.
Extraction only: `openmm`, `openmmtools`.
Tests: `pytest`, `openmm`, `openmmtools`.
Notebooks: `matplotlib`, `py3Dmol` (lazy-imported).


## Coordinate measure boundary (0.2)

`internal.py` depends on `coordinates.py` for reconstruction, `_validation.py`
for precision checks, `batching.py` for mapping, and `extract.py` for pytree registration. It does not evaluate
energy. `utils.py` composes the transform with energy for the physical internal
density and the explicitly named fixed-frame density. See README migration notes.

`sampling_coordinates.py` provides the independent `SamplingCoordinates` map
(log half-lines, logit intervals, unchanged circular axes), inverse and safe
density composition. `_validation._check_log_density` checks callback results
for both coordinate pullbacks. See `docs/sampling_coordinates.md`.
